# 04 — Evidence Ledger

**Conventions**
- File offsets are raw file positions. VAs assume image base `0x140000000`.
- `AltA2DP.sys` section map: `.text` RVA `0x1000` ↔ file `0x400`; `.rdata` RVA `0x96000` ↔ file `0x95000`; `.data` RVA `0xBD000` ↔ file `0xBB800`.
- Disassembly comes from `dumpbin /disasm`. Import names were resolved by parsing the IAT.

## Limitations
- No PDBs: function names, WPP format strings (TMF) and WDF call names are unavailable. KMDF calls go through `WdfFunctions[]` and could not be named without the WDF function-table index map. Doing that would be a reasonable next step.
- No dynamic analysis (the driver was never loaded), so all timing values, defaults and state transitions are static inferences.
- `Docs\3rdparty.html` and `Docs\FAQ.html` are missing.
- External references were used only to *interpret* constants: AOSP libldac, AOSP Bluetooth headers, WDK header knowledge for IOCTL and BRB values.

## Consolidated unknowns
1. AVDTP state machine detail: SUSPEND, ABORT, incoming connections, error codes in `Current\Error`.
2. `{3DAF2019}` property IDs and payload layouts.
3. LDAC call-site parameters: MTU, frames per packet, RTP timestamping, fragmentation.
4. ABR algorithm (product-specific vs libldac).
5. aptX and SBC implementation provenance.
6. Defaults for every registry value, and how changes propagate to the live driver.
7. How the service is installed (start type, account).
